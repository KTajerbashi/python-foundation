# Context Source — پروژه آموزش پایتون

این فایل منبع مرجع زمینه و تصمیم‌های آموزشی پروژه است. در صورت تعارض، دستورالعمل پروژه و آخرین وضعیت ثبت‌شده جلسه ملاک هستند.

## مشخصات یادگیرنده
- زبان آموزش: فارسی
- سطح شروع: مبتدی؛ پیش‌دانسته برنامه‌نویسی فرض نمی‌شود.
- سیستم‌عامل فعلی بر اساس اطلاعات گفتگو: Windows (نسخه دقیق هنوز تأیید نشده).
- محیط پیشنهادی: Python + Visual Studio Code + افزونه رسمی Python.
- منطقه زمانی گفتگو: Asia/Tehran (برای زمان‌بندی درس‌ها ضروری نیست).

## هدف آموزشی
یادگیری عملی پایتون از صفر تا ساخت یک پروژه واقعی، همراه با تمرین، بازخورد، فایل درس و ثبت پیشرفت.

## قواعد ثابت جلسات
- شروع هر جلسه با خط دقیق `شروع جلسه N` که N شماره جلسه است.
- پایان هر جلسه با عبارت دقیق `پایان جلسه`.
- در پایان هر جلسه فایل Markdown مستقل در پوشه `sessions` ایجاد شود.
- گزارش پایان جلسه باید بگوید هنرجو در کدام مرحله و چند درصد از نقشه راه 24 جلسه‌ای قرار دارد.
- جلسه فقط وقتی تکمیل محسوب شود که محتوای جلسه ثبت و وضعیت تمرین‌ها مشخص شده باشد.
- اگر تمرین انجام نشده، وضعیت آن صادقانه «در انتظار بررسی» ثبت شود.
- آموزش فارسی، قدم‌به‌قدم و همراه مثال اجرایی باشد.

## وضعیت شروع
- جلسات تکمیل‌شده: 0 از 24
- جلسه بعدی: 1
- مرحله فعلی: آماده‌سازی پیش از شروع مبانی
- درصد ساختاری مسیر: 0٪
- وضعیت نصب ابزارها: تأیید نشده؛ باید بررسی شود.
- پروژه نهایی: هنوز انتخاب نشده؛ پیشنهاد اولیه مدیریت کارهای روزانه با JSON است.

## ابزارهای پیشنهادی
ضروری:
1. Python 3.14.x نسخه پایدار
2. Visual Studio Code
3. افزونه Python از Microsoft در VS Code

مفید اما فعلاً اختیاری:
- Git برای کنترل نسخه
- Windows Terminal یا PowerShell (در ویندوز معمولاً در دسترس است)
- افزونه Pylance و Python Debugger؛ معمولاً با افزونه Python نصب/پیشنهاد می‌شوند.
- Jupyter فقط زمانی که به نوت‌بوک نیاز پیدا کنیم.

## روش کار با فایل‌ها
- هر جلسه در `sessions/session_XX.md` ذخیره شود.
- پس از پایان جلسه، وضعیت همین فایل و در صورت نیاز این فایل Context Source به‌روزرسانی شود.
- فایل‌ها نباید ادعا کنند نرم‌افزاری نصب یا تمرینی انجام شده مگر اینکه کاربر تأیید کرده یا شواهد آن ارائه شده باشد.
- شماره جلسه بعدی از آخرین جلسه تکمیل‌شده استخراج شود؛ اگر سابقه فایل‌ها در دسترس نیست، از کاربر تأیید بگیر.

## ترجیحات آموزشی
- توضیح ساده و روشن، بدون اصطلاحات سنگین و بدون شتاب.
- مثال‌های کوچک و قابل اجرا.
- تمرین عملی و اصلاح خطا با توضیح علت.
- از ارائه چندین ابزار و کتابخانه غیرضروری در ابتدای مسیر پرهیز شود.
